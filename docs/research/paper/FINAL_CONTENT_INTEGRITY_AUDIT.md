## E. Unsupported Claim Corrections

1. **Cryptographic Provenance:**
   - *Draft claim:* "an immutable SQLite message archive with cryptographic provenance"
   - *Audited reality:* ManiGit calculates SHA-256 content hashes on raw turns and links memory IDs to source message IDs via immutable SQLite foreign key triggers; it does not implement asymmetric cryptographic digital signatures or zero-knowledge cryptographic proofs.
   - *Correction:* Replaced with "commit-linked explicit provenance" and "immutable, content-addressed ground truth." Cryptographic proofs correctly framed as future work (Verifiable Memory Governance).
2. **Public Release / Repository:**
   - *Draft claim:* "All code, datasets, and configurations are released for complete reproducibility."
   - *Audited reality:* The code, evaluation harness, and benchmark outputs exist within the local project workspace but are not hosted on a public domain.
   - *Correction:* Replaced with "The evaluation pipeline, experiment configurations, and raw benchmark artifacts are organized to support reproducibility."
3. **Exact Knapsack Optimization:**
   - *Draft claim:* Could be misread as claiming ManiGit solves the NP-hard 0-1 Knapsack problem exactly.
   - *Correction:* Section VI explicitly states: *"ManiGit does not solve the exact combinatorial optimization problem at inference time; instead, this formulation motivates our practical system design, which uses local lexical retrieval, tier/confidence/priority scoring signals, and a deterministic greedy score-density selection algorithm."*
4. **Novelty & Literature Scoping:**
   - *Draft claim:* Broad unquantified statements regarding "all agent memory systems."
   - *Correction:* Section IV grounded to the specific reviewed literature corpus: *"Among the 34 papers reviewed in our literature corpus, only 5 (14.7%) explore any versioning concepts, and none integrate automated DAG commit tracking with budget-constrained knapsack context compilation."*

## I. Remaining Limitations

1. **Synthetic Dialogue Evaluation:** Benchmarks are based on carefully designed multi-turn synthetic dialogue scenarios rather than human-in-the-loop multi-day production logs.
2. **Deterministic Model Adapter:** Experiments utilize a deterministic mock model adapter with fixed seed 42 to isolate architectural memory mechanisms from frontier LLM non-determinism.
3. **Lexical Retrieval Engine:** The current reference implementation utilizes Okapi BM25 and exact lexical matching; dense embeddings and cross-encoders are left for future work.
